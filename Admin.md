### Admin — Dashboard

Halaman dashboard admin diakses lewat `/admin/dashboard` dan ditangani oleh `AdminDashboardController::index`. Controller ini mengumpulkan statistik global sistem: jumlah total siswa (`totalStudents`), guru (`totalTeachers`), kelas (`totalClassrooms`), dan misi (`totalMissions`). Selain itu, halaman menampilkan daftar 5 user terbaru dengan detail `id`, `name`, `email`, `role`, `avatar`, dan `created_at`. View yang dirender adalah index.tsx dengan layout `AdminLayout`, yang menampilkan banner sambutan dengan tombol "Kelola User", grid statistik empat kartu (siswa, guru, kelas, misi), tabel overview user terbaru, dan panel `SystemHealth` untuk status sistem. Dashboard admin berfungsi sebagai pusat monitoring keseluruhan aplikasi, memberikan gambaran cepat tentang jumlah entitas utama dan aktivitas terbaru, serta akses langsung ke halaman kelola user.

### Admin — Kelola User (Index)

Halaman daftar user diakses lewat `/admin/users` dan dikontrol oleh `AdminUserController::index`. Controller menggunakan `AdminUserService::getPaginatedUsers` untuk mengambil user dengan filter role (`all`, `student`, `teacher`, `admin`) dan pencarian nama/email, serta statistik total user per role. View index.tsx menampilkan `UserStats` (empat kartu statistik total user, siswa, guru, admin), `UserFilters` untuk dropdown role dan input pencarian, `UserTable` yang menampilkan tabel user dengan kolom nama, username, email, role, XP/level, dan tombol edit/hapus, serta pagination. Setiap baris user memiliki tombol edit yang mengarah ke `/admin/users/{id}/edit` dan tombol hapus yang memunculkan konfirmasi SweetAlert sebelum memanggil `DELETE /admin/users/{id}`. Halaman ini memungkinkan admin melihat semua user sistem, memfilter berdasarkan role atau mencari spesifik, dan melakukan aksi CRUD dasar.

### Admin — Tambah User Baru (Create)

Halaman form tambah user diakses lewat `/admin/users/create` dan dikontrol oleh `AdminUserController::create`. Controller hanya merender view create.tsx tanpa data tambahan. View ini menampilkan form dengan field: nama, username, email, password, konfirmasi password, role (dropdown: student/teacher/admin), dan upload avatar. Form menggunakan validasi client-side dan server-side via `StoreUserRequest`. Setelah submit, data dikirim ke `POST /admin/users` yang memanggil `AdminUserService::createUser` untuk membuat user baru dengan hashing password dan menyimpan avatar jika ada. Setelah sukses, redirect ke `/admin/users` dengan notifikasi sukses. Halaman ini memungkinkan admin menambahkan user baru ke sistem dengan semua atribut wajib.

### Admin — Edit User (Edit)

Halaman form edit user diakses lewat `/admin/users/{id}/edit` dan dikontrol oleh `AdminUserController::edit`. Controller mengambil data user spesifik dan merender view edit.tsx dengan data user pre-filled: `id`, `name`, `username`, `email`, `role`, `avatar`, `xp`, `level`. View menampilkan form serupa dengan create, namun field password opsional (untuk ganti password), dan avatar bisa diganti atau dihapus. Form submit ke `PUT /admin/users/{id}` yang memanggil `AdminUserService::updateUser` untuk update data, termasuk upload avatar baru atau hapus yang lama. Setelah sukses, redirect ke `/admin/users` dengan notifikasi. Halaman ini memungkinkan admin mengubah semua atribut user kecuali ID, dengan validasi untuk mencegah duplikasi username/email.

### Admin — Kelola Kelas (Index)

Halaman daftar kelas diakses lewat `/admin/classrooms` dan dikontrol oleh `AdminClassroomController::index`. Controller menggunakan `AdminClassroomService` untuk mengambil kelas dengan filter teacher, tahun ajaran, dan pencarian nama, serta statistik total kelas, total siswa, rata-rata siswa per kelas, dan kelas paling populer. View index.tsx menampilkan `ClassroomStats` (empat kartu statistik), `ClassroomFilters` untuk dropdown teacher, tahun ajaran, dan input pencarian, grid kartu kelas (`ClassroomCard`) yang menampilkan nama kelas, tahun ajaran, kode gabung, nama guru, jumlah siswa, dan tombol edit/hapus/manage siswa, serta pagination. Setiap kartu memiliki tombol edit ke `/admin/classrooms/{id}/edit`, hapus dengan konfirmasi SweetAlert, dan manage siswa ke `/admin/classrooms/{id}/students/manage`. Halaman ini memungkinkan admin melihat semua kelas, memfilter berdasarkan guru atau tahun, dan akses ke aksi CRUD kelas.

### Admin — Tambah Kelas Baru (Create)

Halaman form tambah kelas diakses lewat `/admin/classrooms/create` dan dikontrol oleh `AdminClassroomController::create`. Controller mengambil daftar semua guru via `AdminClassroomService::getAllTeachers` dan merender view create.tsx. View menampilkan form dengan field: nama kelas, tahun ajaran (dropdown), guru pengampu (dropdown dari daftar guru), dan kode gabung (auto-generated atau manual). Form menggunakan validasi via `StoreClassroomRequest`. Setelah submit, data dikirim ke `POST /admin/classrooms` yang memanggil `AdminClassroomService::createClassroom` untuk membuat kelas baru dengan generate kode gabung unik. Setelah sukses, redirect ke `/admin/classrooms` dengan notifikasi. Halaman ini memungkinkan admin membuat kelas baru dengan assign guru dan tahun ajaran.

### Admin — Edit Kelas (Edit)

Halaman form edit kelas diakses lewat `/admin/classrooms/{id}/edit` dan dikontrol oleh `AdminClassroomController::edit`. Controller mengambil data kelas spesifik dan daftar guru, merender view edit.tsx dengan data pre-filled: `id`, `name`, `academic_year`, `teacher_id`, `join_code`, dan `students_count`. View menampilkan form serupa create, namun kode gabung bisa diubah (dengan validasi unik). Form submit ke `PUT /admin/classrooms/{id}` yang memanggil `AdminClassroomService::updateClassroom` untuk update data. Setelah sukses, redirect ke `/admin/classrooms` dengan notifikasi. Halaman ini memungkinkan admin mengubah nama, tahun ajaran, guru, dan kode gabung kelas.

### Admin — Kelola Siswa Kelas (Manage Students)

Halaman manage siswa kelas diakses lewat `/admin/classrooms/{id}/students/manage` dan dikontrol oleh `AdminClassroomController::manageStudents`. Controller mengambil siswa yang sudah di kelas (`classroomStudents`) dan siswa tersedia (`availableStudents` via `AdminClassroomService::getAvailableStudents`). View manage-students.tsx menampilkan header dengan info kelas, statistik siswa terdaftar/tersedia/kode gabung, dan dua kolom utama: "Siswa di Kelas" (daftar siswa saat ini dengan tombol hapus) dan "Siswa Tersedia" (daftar siswa belum masuk kelas dengan tombol tambah). Ada input pencarian untuk filter siswa di kedua kolom. Form submit ke `POST /admin/classrooms/{id}/students` yang memanggil `AdminClassroomService::updateClassroomStudents` untuk sync relasi `classroom_user`. Setelah sukses, notifikasi dan reload halaman. Halaman ini memungkinkan admin menambah/hapus siswa dari kelas secara drag-and-drop visual, dengan pencarian dan konfirmasi perubahan.
